Think Fast: Local Decision Models

Pick a real problem made of small judgment calls. Build a decision model for it that runs on your own hardware and gives honest probabilities. Prove it on data it has never seen, then put it to work: automate the calls it is sure about and send the rest to a person.

What a decision engine does

It reads the input once and returns a probability for every answer you defined. It writes no text.

Six steps

Each step is a demo on its own. Go as far as you can.

  1. Pick a problemJudgment calls someone makes often, today by hand, with rules or with a big hosted model. Say who has it, what it costs them and why it should run locally.
  2. Build the engineA model that answers with probabilities on your machine: Kev, a small open model through the bridge, or a classic classifier. On the decision API, the kit's runner scores it for you.
  3. Prove itHold out test data you never train, prompt or tune on. Put a simple baseline next to your model. Show your confidence is honest: when it says 90%, it is right 9 times in 10.
  4. Make it yoursFine-tune, distil a bigger teacher into a small student, train a new head, or label your own data. Show what each change gained.
  5. Make it fast and cheapMeasure latency and cost per million decisions next to a hosted model. Run it with Wi-Fi off.
  6. Put it to workA tool for the people with the problem: automate above a threshold, send the rest to a review queue, report the share automated within your error budget.

Pick a problem

Three ways in. Whichever you take, hold out a test set before you start tuning.

Your own

Routing, policy checks, deduplication, triage: calls someone makes thousands of times. Your data, or any public data you're allowed to use.

Dataset Factory

Ready-made yes/no tasks from public data, with time-ordered splits and baselines to beat. Check each licence; link the data, don't commit it.

Our starter problem

Five data-work task families, a messy catalogue, a scorer and baselines, all in this kit. Below.

Is it a good problem? Airbnb's four tests for when a small tuned model pays off: the volume is high, the latency is tight, you need a threshold rather than a verdict, and you have labelled data. Their 2B model matched frontier models on one policy check at a median 35 ms and about 1% of the cost (the benchmark).

Your 5-minute demo, in this order

  1. The problem (~45 s): who makes these calls, how often, what it costs, why local.
  2. Live (~2 min): your tool on real inputs. What it decided alone, what it sent to a person, and why. Turn Wi-Fi off on screen first.
  3. The evidence (~1.5 min): held-out numbers next to your baseline, your threshold, how honest your confidence is.
  4. What you built (~45 s): what you trained, tuned or invented, what it gained, your limits.

Then 3 minutes of questions. Your 3-minute video follows the same order; the jury watches it if the live demo breaks.

Quick start (starter problem)

Needs uv. The kit itself is plain Python 3.11+ with no dependencies.

1. Get the kit and generate the data 
git clone https://github.com/proximata/hackathon-26-think-fast.git && cd hackathon-26-think-fast
uv run python -m thinkfast.suite      # data/dev.jsonl
uv run python -m thinkfast.messy      # data/catalogue_messy.csv + answer key
2. Start an engine on port 8009 (Kev, in its own folder) 
git clone https://github.com/jaredpalmer/kev.git && cd kev
uv sync --extra serve
uv run --extra serve python -m kev.serve --run jaredpalmer/kev-0.8b --port 8009
3. Score it (from the kit folder) 
uv run python -m thinkfast.run_eval --suite data/dev.jsonl --limit 200   # quick check
uv run python -m thinkfast.run_eval --suite data/dev.jsonl               # full dev suite

Prefer your own model? thinkfast/bridge.py turns any local OpenAI-compatible server that returns top_logprobs into an engine. See the README.

Lessons from our dry run

  • Download everything the night before.Kev's install pulled a 6.9 GB environment (6.6 min), and the first start took about 10 more minutes for the weights. Venue Wi-Fi will be shared.
  • Turn thinking off for chat models.Qwen3.5 starts its reply with “Thinking”, so the bridge finds no answer letter and every question becomes a uniform guess. With llama.cpp, start llama-server with --reasoning off.
  • Rehearse with Wi-Fi off.Start your engine from your own README and run the evaluation without a network. Kev restarted offline in 91 s from cached weights.
  • A small GPU is enough to start.Kev-0.8B ran on a 4 GB laptop GPU, using 3.9 GB. Speed depends mostly on hardware and kernels.
  • Calibrate on data you didn't fit on.One temperature fitted on half the dev answers cut Kev's calibration error on the other half from 0.078 to 0.047.

House rules

  • Any model, any data you're allowed to use. Cloud is fine for training and labelling. Hosted models at decision time are allowed but score low on C.
  • Respect every licence and terms of service, including those of any model you generate training data with. Data you may not redistribute is linked, not committed.
  • Test on data you never trained, prompted or tuned on.

Submit

  • The standard submission: public MIT repo in the proximata organisation, README, 3-minute video, written submission.
  • A REPORT.md that starts with the scorecard from docs/REPORT_TEMPLATE.md.
  • One command that reproduces your held-out numbers.

Reading the numbers

Held-out test set
Data you never trained, prompted or tuned on. Your numbers only count here.
Baseline
The simplest thing that could work: the most common answer, a few rules, a logistic regression.
Accuracy
Share of questions where your most likely answer is right.
Brier score
How far your probabilities are from the truth. 0 is perfect, lower is better.
Calibration error
Gap between how sure you say you are and how often you're right.
Automation rate
Share of decisions you can take alone with at most 5% errors. The runner's headline number.
F1, AUC
Common yes/no metrics: F1 balances missed and false alarms at one threshold; AUC ranks across all thresholds.
p95 latency
95% of requests finish faster than this.
